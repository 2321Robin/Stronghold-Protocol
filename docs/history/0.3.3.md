## 36. 0.3.3（未发布）

### 36.1 第一期商店装备核查与空栏显示（round53 shopequip，2026-10-25）

维护者在 0.3.2 的第一期游玩中报告「商店一直没有装备」，并确认官方第一期会出售装备。本次接受这条
亲历事实，以对应时期的官方表确定开放等级；没有将第二期的开放等级移植给第一期。

#### 复现结论与修正范围

对 `act1autochess`、`act1autochess@V1_1`、`act2autochess@V2_1` 的全部大厅模式（单人／四人 ×
标准 FUNNY／险境 NORMAL／绝境 HARD）各从 1 升至 6 级，升级后主动刷新，每名玩家购买装备。
在改动前即得到下表结果：第一期两个版本都在 5–6 级正常出售，第二期上半在 1–6 级正常出售。
本次没有复现「满足等级并刷新后仍永远没有装备」，不能把它宣称为已找到根因的服务端缺货问题。

确认的客户端问题：`shopBar.js` 按现存卡片的 `kind` 划分两栏，把所有 `null` 都当干员空位；第一期
4→5 级新增的装备位恰好是 `null`，因此跑到干员栏，装备区则错误显示 `SOLD OUT / 已购买`。
1–4 级根本没有装备位时也显示「已购买」。修正为服务端 `m.private.shop.layout` 发送实际干员／装备
位数，客户端据此定位空栏；装备位打开而未刷新时使用现有「空栏位：刷新或下回合开始时补满」提示，
未开放时不画售罄卡。已购买的真实装备仍显示「已购买」。抽取、库存、价格、升级后不自动补货的规则不变。
旧存档／mock 没有 layout 时仍按卡片种类推断（兼容处理；[ASSUMED]，无法恢复旧帧中 `null` 的原始种类）。

三个版本均用 `--version <id> --offline --quiet` 重新生成，全部输出字节不变。

#### 其他 mode 字段与装备入口

同时比较每个版本所有 mode 字段。第一期与默认实际不同的字段为 `activeBondIds`、`bossRound`、
`bossWeights`、`color`、`combatTimeLimit`、`desc`、`effectDescList`、`enemyScale`、`hiddenBossWeights`、
`inactiveBondIds`、`inactiveEnemyKeys`、`lastRound`、`rounds`、`shopSlots`、`spRounds`、`stages`、
`unlockText`、`upgradePrices`；现有构建已经保留这些差异。第二期上半的现存 mode 条目与默认相同，
但没有尚未开放的终极模式，这是对应快照的数据，不是误复制。新增测试直接核对每个模式的官方名称、类型、
难度、说明、盟约、禁用敌人、商店各级字段，以及 `autoChessData.turnInfoDataDict[modeId][round]` 的
休整时间与活动 `battleDataDict` 的机变标记。未找到需修改的明确错误 mode 映射。

道具补给／机密商店：在每版每个实际安排该家族的机变回合检查抽卡、合法装备 ID、零价格与领取后的库存；
不是每种单人模式都有这两类事件（例如单人险境只有 R6 补给与 R9 战术），不人为增加机变家族。
每个 `choices.pools` 的 `kind: equip` 池检查显式 ID 属于本版本、1／6 级可抽取，以及按商店等级限制的池；
装备奖励检查 `pushItemOffer → privateView → g.reward` 确实发到玩家库存。第一期的 shop-eligible 正常装备
为 38 件，第二期上半为 51 件，精英装备不进入正常商店池。

尚未解决的旧数据证据缺口仍见 [DATA.md](../DATA.md)「Carried over unreviewed [ASSUMED]」：
第一期共用的阶级库存数、部分奖励／机变概率、经济字面量与缺失研究资料的回退等。官方 shopLevel 表没有
提供这些数值，本次不把未经证实的调整当作装备缺货修复。要继续复现维护者的原报告，需要具体模式、
调度中心等级、刷新后的画面或可重放对局；当前核查只能确认上述空栏显示错误。
